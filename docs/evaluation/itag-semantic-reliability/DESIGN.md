# Catalog design

Each invocation builds a catalog over the immutable graph and evaluated candidate. Aliases contain a deterministic index and 128 bits of the full graph/candidate hash. Graph, revision, candidate or history changes alter the catalog. Mapping is local to the invocation and never reused as an authorization token.

The catalog retains every node and relationship with trust classification and record identity. Repeated serialized Shield reports become status summaries. Tool bodies have a 400-character preview and an explicit truncation flag plus hash, with full records retained in the graph. A truncated preview can require an uncertain semantic assessment. Generic redaction masks credential-looking fields. A separate scope_role carries the operator-validated intent designation because generic authorization-name redaction masks authorization_source in model context.

Judgment is a strict extra-forbidden Pydantic schema. The model selects candidate, task and supporting aliases, relationship, drift and uncertainty. Two literal field selectors identify objective and rationale. The server resolves their exact contents, checks the selected active authenticated IntentSpec and candidate, and constructs canonical references only from selected records. It never fills in a missing scope selection. Numerical values, receipts, source trust and budget projections remain server facts. The recorded source ASSISTANT describes the candidate proposal, and implies no causal tool influence.

Schema errors and unsupported selections fail closed. The v3 path performs one inference without repair. Legacy canonical-ID responses continue through the pre-existing strict validator and bounded citation-link repair so saved clients and fixtures remain compatible. The configured generic provider uses chat/Responses output plus strict local validation. This change does not assert native JSON Schema support on DeepSeek.

A valid citation establishes record identity and relevance of the selected objective/candidate comparison. It cannot mathematically prove the semantic meaning of unrestricted prose. Explanation JSON labels semantic text MODEL_INFERENCE and includes server-resolved anchors. Canonical graph checks, temporal policies, SDE, signer revalidation and contract enforcement remain separate gates.

The v3.0 quotation design failed mainly because the model selected extracted tasks as objective support and sometimes repeated financial fields where the rationale quote was expected. v3.1 field selection fixed quotation copying, but generic pre-execution caveats escalated benign cases. v3.2 clarifies proposed contribution and numeric-policy responsibility. The original failed measurements are retained. The final local refinement bounds repeated tool bodies after an Anvil context-budget failure. Provider measurements precede that last bounded-preview refinement.

A small legacy projection remains in the prompt for existing deterministic fixture consumers. It does not create graph edges. Task IDs still identify active USER-source extracted tasks. Authenticated scope and extracted tasks retain their distinct trust levels. Qualitative judgments remain the model's responsibility.
