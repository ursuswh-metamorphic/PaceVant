# Gas credit for the single Demo User

> **DOC STATUS: MODULE_REFERENCE** - local interface/contribution reference, not a live readiness certification. The [current system design](../../../../../docs/AI_Treasury_Security_System_Design_v2.1.md) owns the complete architecture/status; old reports linked below remain checkpoint-scoped.

This module maintains a sponsor-allocated allowance in the **existing execution SQLite DB**. It is a prepaid-style internal credit, not an on-chain deposit, the demo wallet AVAX balance, a swap budget, or a certified risk budget. It never signs, broadcasts, invokes a model or changes treasury authorization.

`GasCreditLedger(path, config, chain_id, vault, relayer, confirmations)` binds one account to an immutable scope. `begin_request(key, goal)` allocates one workflow identity once; a matching repeated key returns that identity and a different body conflicts. `bind_build(workflow, build)` attaches billing only to workflows accepted by the authenticated demo API. Operator workflows remain separate. `account()` returns public amounts/history only.

`reserve(db, build, tx, maximum, relayer_balance)` runs inside the SAME execution SQLite transaction that inserts the signed send journal. The relayer must not send until that transaction commits. Maximum is the signed legacy transaction `gasLimit * gasPrice`, including its small estimate margin. It checks per-transaction ceiling, unspent/unreserved credit and physical relayer balance. All money is integer wei stored as decimal TEXT. `BEGIN IMMEDIATE` serializes competing reservations; tx hash/build uniqueness prevents double holds.

`reconcile(report, invalidated=False)` consumes the existing shared outcome verifier through `OutcomeMonitor.fee_observer`. It requires canonical, gas-verified facts and the configured confirmation depth, chain/vault/build/relayer identity. Actual charge is exactly `gasUsed * effectiveGasPrice`; both SUCCESS and REVERTED receipts incur gas. A verified gas fee may be recorded even when outcome effects require review (`MISMATCH`); fee settlement does not approve the swap outcome.

Pending/unavailable/unknown outcomes keep the maximum hold, with no charge or automatic release. On reorg, an immutable reversal restores the old charge but returns the transaction to `REORG_HOLD`; canonical re-inclusion settles once again. Projection state and append-only events update atomically. Deep reorgs can make available credit negative if later trades used previously released headroom; further sends are blocked until review/reconciliation. The account is intentionally conservative about dropped/expired unknown submissions; there is no unsafe timeout-based refund.

Tables: `demo_account`, `demo_requests`, `demo_builds`, `demo_gas_reservations`, `demo_gas_events`. Restart or changing the initial-credit env **does not refill** an existing account. Scope changes fail startup. There is no public top-up/refund endpoint; a real payment/deposit product is outside this demo. Preserve this DB with control history and transaction journals; never delete it to fix a pending request.
